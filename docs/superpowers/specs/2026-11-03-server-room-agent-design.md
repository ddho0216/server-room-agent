# 서버실 AI 부사수 — 설계 문서

작성일: 2026-11-03 / 목표 마감: 2026-11-15 23:00 (비즈테크아이 신입 인턴 AI 엔지니어 지원)

## 1. 목적과 성공 기준

**목적**: IDC 관제 2년 3개월 경력과 AI 엔지니어링을 이어 주는 포트폴리오를 만든다. 화면은 데이터센터 서버실이고, 사용자는 랙 하나를 맡은 서버 관리자다. AI는 신입 부사수로서 도구를 직접 써서 확인하고, 상태를 바꾸는 행동은 사람의 승인을 받아 실행한다.

**성공 기준**
- 링크 하나로 면접관이 바로 써 볼 수 있다 (Vercel 배포).
- AI가 말만 하지 않고 도구를 호출해 DB의 서버 상태를 읽고 바꾼다.
- 모든 AI 행동이 `action_log`에 남는다.
- API 키와 DB 키가 공개 파일, GitHub, 브라우저에 없다.
- 자소서에는 실제로 끝낸 단계까지만 쓴다.

## 2. 정직 규칙

- 서버 상태, 고객 문의, 보고서는 전부 가상 데이터다. 실제 회사, 고객사, 센터 이름과 실제 양식은 넣지 않는다.
- 자소서와 이력서에는 완료한 단계 기준으로만 쓴다 (예: 4단계가 끝나기 전에는 "AI 에이전트를 만들었다"고 쓰지 않는다).
- 네트워크관리사 2급은 "필기 합격, 실기 예정"으로 쓴다.

## 3. 구조

| 구성 | 역할 | 비고 |
|---|---|---|
| 화면 (정적 페이지) | 서버 랙 1개, 서버 4대, 불빛·온도·경고 표시, 부사수 대화창, 승인 버튼 | 키 없음, DB 직접 접근 없음 |
| 서버 함수 (Vercel `api/`) | 상태 조회, 사고 발생, 에이전트 호출, 승인 처리 | 비밀 키는 환경변수에만 |
| 데이터 (Supabase) | `servers`, `incidents`, `action_log`, `pending_actions`, `reports`, `tickets` | RLS 켬, anon·authenticated에 권한 없음 |
| AI (Claude API) | 서버 함수에서만 호출 | 모델은 환경변수로 교체 가능 |

저장소, Supabase 프로젝트, Vercel 프로젝트는 방어전과 분리해 새로 만든다. 방어전에서는 폴더 구조와 진행 방식(AGENTS.md, README 단계 기록, 단계별 완료 기준)만 가져오고 강사 자료는 넣지 않는다.

## 4. 에이전트 동작

### 도구
| 도구 | 종류 | 승인 |
|---|---|---|
| `get_server_status` | 읽기 | 불필요 |
| `get_cooling_temp` | 읽기 | 불필요 |
| `read_logs` | 읽기 | 불필요 |
| `restart_fan` | 변경 | 필요 |
| `open_ticket` | 변경 | 필요 |
| `save_report` | 변경 | 필요 |

### 흐름
1. 사용자가 말하거나 사고 경고가 뜬다.
2. 서버 함수가 대화와 도구 정의를 Claude에 보낸다.
3. 읽기 도구는 즉시 실행하고 결과를 다시 보낸다 (최대 반복 횟수 제한).
4. 변경 도구는 실행하지 않고 `pending_actions`로 저장한 뒤 화면에 승인 요청을 보낸다.
5. 사용자가 승인하면 실행하고 `action_log`에 기록한다. 거절해도 기록한다.

### 시나리오 (네가 실제로 한 일에서 가져옴)
| 시나리오 | 내용 | 단계 |
|---|---|---|
| 순회 점검 | 화면 시계가 3시가 되면 서버 4대와 냉각기 상태를 읽고 "이상 없음 / 확인 필요" 보고서를 쓴다 | 4 |
| 사고 대응 | 온도 상승, 디스크 경고, 네트워크 끊김 중 하나가 발생하면 확인하고 조치를 제안한다 | 4 |
| 월간 보고서 | 한 달 치 `incidents`와 `action_log`로 보고서를 만들고 지난달 양식과 달라진 곳을 먼저 알린다 | 5 |
| 고객 문의 접수 | 문의 글을 분류하고 긴급도와 답변 초안, 티켓을 만든다 | 5 |

해당하지 않는 일: KVM 연결, 케이블 포설 등 몸으로 하는 일.

## 5. 데이터 모델 (초안)

- `servers(id, name, rack_pos, status, temp_c, fan_ok, updated_at)`
- `incidents(id, server_id, type, severity, started_at, resolved_at)`
- `action_log(id, actor, tool, input, result, approved_by, created_at)`
- `pending_actions(id, tool, input, status, created_at)`
- `reports(id, kind, period, body, created_at)`
- `tickets(id, source, category, priority, body, status, created_at)`

모든 테이블 RLS 켬. `owner_id` 칸은 방어전과 같은 방식으로 미리 둔다.

## 6. 안전장치

- 키는 Vercel 환경변수에만 둔다. 클라이언트 번들과 `data.json` 같은 공개 파일에 비밀과 상태가 없다.
- 하루 호출 횟수 제한, 입력 길이 제한, 에이전트 도구 반복 횟수 제한.
- 변경 도구는 항상 승인 후 실행.
- 쓰기 요청과 승인 요청은 서버에서만 검증한다.
- 5단계에서 비로그인 요청으로 읽기/쓰기를 시험하고 결과를 README에 기록한다.

## 7. 단계와 완료 기준

| 단계 | 내용 | 완료 기준 | 목표일 |
|---|---|---|---|
| 1 | 서버실 화면 + 배포 | Vercel 주소에서 서버 4대가 보이고, 저장소가 공개이며 README에 단계 기록이 있다 | 11/5 |
| 2 | Supabase로 데이터 이동 + 잠금 | 서버 상태가 테이블에 있고 RLS가 켜져 있으며 공개 파일에는 상태 데이터가 없다 | 11/6 |
| 3 | 서버 함수 | 화면이 `/api`로만 상태를 읽고, 사고를 발생시킬 수 있다 | 11/8 |
| 4 | AI 부사수 | 순회 점검과 사고 대응이 도구 호출과 승인으로 동작하고 `action_log`에 남는다 | 11/10 |
| 5 | 제한·보안 + 시나리오 추가 | 호출 제한이 작동하고 비로그인 공격 시험 기록이 있으며, 월간 보고서와 고객 문의 접수 중 최소 하나가 동작한다 | 11/13 |
| 6 | 정리 | README, 한 줄 설명, 자소서용 문단, 스크린샷 | 11/14 |

예비일: 11/15 오전. 지원서 제출은 11/15 23:00 전에 한다.

## 8. 직접 준비할 것

## 9. 하지 않는 것

- 방어전 강사 자료 복사
