# 서버실 AI 부사수

데이터센터 서버실 랙 하나를 맡은 관리자가 되어, 부사수 에이전트와 함께 순회 점검과 장애 대응을 하는 작은 프로젝트입니다. 모든 서버 상태는 가상 데이터입니다.

**부사수는 규칙으로 움직이는 시뮬레이션입니다(AI 모델을 쓰지 않습니다).** 도구 호출, 사람 승인, 작업 기록은 실제로 동작하고, 모델이 들어갈 자리(`lib/agent.mjs`의 클라이언트)는 분리해 두었습니다. 기본값은 규칙 뇌(`lib/rule-brain.mjs`)이고, 환경변수 `LLM_PROVIDER`로 다른 제공자로 바꿀 수 있게 설계했습니다.

## 현재 기능

- 서버 4대가 들어 있는 서버 랙 화면 (정상 3대, 주의 1대). 상태에 따라 LED 색이 바뀌고, 주의 서버는 깜빡입니다.
- 서버 이름에 HTML이 들어 있어도 글자로만 표시됩니다.
- 서버가 없거나 모르는 상태값이면 안내 문구와 회색 LED로 표시됩니다.
- 모션 줄이기 설정에서는 깜빡임이 꺼집니다.
- 서버 상태는 Supabase `servers` 테이블에 있고, 화면은 서버 함수 `GET /api/servers`로만 읽습니다. 공개 파일에는 서버 데이터가 없습니다.
- 서버 함수는 GET만 받고(그 외 405), 설정이 없으면 500, Supabase가 실패하면 502를 돌려줍니다. 응답에 키는 없습니다.
- 불러오지 못하면 "불러오지 못했어요" 안내를 보여 줍니다.
- 화면의 사고 조작판에서 서버와 사고(온도 상승, 디스크 경고, 네트워크 끊김)를 골라 `POST /api/incidents`로 사고를 만들고, `POST /api/reset`으로 처음 상태로 되돌립니다.
- 사고 요청은 입력을 검증합니다(종류 목록 밖 400, 없는 서버 404, POST 아님 405). 10분 안에 10건을 넘으면 429로 거절합니다(전체 공통 한도).
- 서버 앞판, 드라이브 칸, 통풍구, 돌아가는 팬, 바닥 타일로 서버실처럼 보이게 꾸몄습니다. 외부 이미지나 라이브러리는 쓰지 않습니다.
- 부사수에게 "순회 점검 해줘", "db-01 확인해 줘", "냉각기 온도 알려줘", "기록 보여 줘", "순회 보고서 써 줘", "db-01 티켓 열어 줘"라고 말할 수 있습니다(`POST /api/agent`). 읽기 도구(서버 상태, 냉각기 온도, 기록 읽기)는 바로 쓰고, 상태를 바꾸는 도구(팬 재가동, 티켓 열기, 보고서 저장)는 **제안만 하고 승인 대기**에 올립니다.
- 화면의 "승인 대기" 카드에서 승인하거나 거절합니다(`POST /api/approve`). 같은 승인을 두 번 눌러도 한 번만 실행되고 두 번째는 409입니다. 승인·거절, 부사수가 쓴 도구, 부사수 호출이 모두 `action_log`에 남고 "최근 활동"에 보입니다(`GET /api/activity`).
- 부사수 요청은 300자까지, 모델(규칙) 호출은 최대 6회, 1시간에 20번까지입니다(전체 공통 한도, 초과 429).

배포 주소: https://server-room-agent.vercel.app

## 실행 방법

```bash
npm test
python -m http.server 8080 -d public
```

두 번째 명령 후 브라우저에서 `http://localhost:8080`을 엽니다.

## 가상 자료 안내

화면의 서버 이름, 온도, 상태는 모두 가상입니다. 실제 회사나 센터의 자료는 없습니다.

### 4단계 완료 기준 확인 (2026-11-04, 배포 주소 기준, 키·결제 없음)

- [x] 순회 점검이 도구 호출로 동작한다: "순회 점검 해줘" → `get_server_status`, `get_cooling_temp` 확인 → `db-01`(팬 멈춤)에 `restart_fan` 제안(승인 대기), 이때 서버는 그대로

- [x] 사고 대응이 승인 흐름으로 동작한다: 티켓 제안 → 승인(`티켓을 열었어요`), 보고서 제안 → 승인(`보고서를 저장했어요`), 거절하면 서버가 바뀌지 않음, 디스크 사고 → `open_ticket`(디스크 경고) 제안
- [x] 모든 행동이 `action_log`에 남는다(`user:agent_run`, `agent:<도구>`, 승인·거절)
- [x] 잘못된 입력을 거절한다: 빈 메시지·공백·숫자·301자·깨진 본문 400, GET 405, 없는 승인 id 409, 없는 서버(`zzz-9`)를 말하면 "확인하지 못했어요"
- [x] 응답과 화면 코드에 키 흔적이 없고, 공개 코드에 서버 이름이 없다. `/lib/…`, `/supabase/…`, `/.env`, `/package.json`은 404
- 배포에서 시험하지 않은 것: 1시간 20번 한도(429)는 단위 시험으로만 확인했다. 한도 시험은 기록을 20건 쌓아 한동안 부사수를 막기 때문이다.

### 막혔던 점

- 처음에는 유료 AI 서비스를 쓰는 설계였으나, 결제 없이 만들기 위해 "뇌"만 규칙 기반으로 바꿨다. 에이전트 루프, 도구 6개, 승인, 기록, 화면은 그대로 쓰고 모델 자리만 갈아끼우는 구조라 큰 수정이 필요 없었다.

- 서버 함수가 502를 돌려주었다. 로그에 `status: 403`이 남아 있어 원인이 테이블 읽기 권한임을 알았다. Data API 자동 공개를 끈 프로젝트라 서버 전용 역할에 `grant select`가 필요했다.
