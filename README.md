# 서버실 AI 부사수

데이터센터 서버실 랙 하나를 맡은 관리자가 되어, AI 부사수와 함께 순회 점검과 장애 대응을 하는 작은 프로젝트입니다. 모든 서버 상태는 가상 데이터입니다.

## 현재 기능

- 서버 4대가 들어 있는 서버 랙 화면 (정상 3대, 주의 1대). 상태에 따라 LED 색이 바뀌고, 주의 서버는 깜빡입니다.
- 서버 이름에 HTML이 들어 있어도 글자로만 표시됩니다.
- 서버가 없거나 모르는 상태값이면 안내 문구와 회색 LED로 표시됩니다.
- 모션 줄이기 설정에서는 깜빡임이 꺼집니다.
- 서버 상태는 Supabase `servers` 테이블에 있고, 화면은 서버 함수 `GET /api/servers`로만 읽습니다. 공개 파일에는 서버 데이터가 없습니다.
- 서버 함수는 GET만 받고(그 외 405), 설정이 없으면 500, Supabase가 실패하면 502를 돌려줍니다. 응답에 키는 없습니다.
- 불러오지 못하면 "불러오지 못했어요" 안내를 보여 줍니다.
- 화면의 사고 조작판에서 서버와 사고(온도 상승, 디스크 경고, 네트워크 끊김)를 골라 `POST /api/incidents`로 사고를 만들고, `POST /api/reset`으로 처음 상태로 되돌립니다.
- 사고 요청은 입력을 검증합니다(종류 목록 밖 400, 없는 서버 404, POST 아님 405). 10분 안에 10건을 넘으면 429로 거절합니다(전체 공통 한도).
- 서버 앞판, 드라이브 칸, 통풍구, 돌아가는 팬, 바닥 타일로 서버실처럼 보이게 꾸몄습니다. 외부 이미지나 라이브러리는 쓰지 않습니다.

배포 주소: https://server-room-agent.vercel.app

## 실행 방법

```bash
npm test
python -m http.server 8080 -d public
```

두 번째 명령 후 브라우저에서 `http://localhost:8080`을 엽니다.

## 가상 자료 안내

화면의 서버 이름, 온도, 상태는 모두 가상입니다. 실제 회사나 센터의 자료는 없습니다.

### 3단계 완료 기준 확인 (2026-11-04, 배포 주소 기준)

- [x] 사고를 만들고 되돌릴 수 있다 (`cache-01` 온도 사고 → `warn`/86°C/팬 정지/`temp`, `web-01` 네트워크 사고 → `down`, `POST /api/reset` → 처음 4대, 두 번 불러도 같은 결과)
- [x] 잘못된 입력을 거절한다 (종류 `fire` 400, 없는 서버 404, 본문이 문자열이거나 JSON이 아니면 400, GET은 405)
- [x] 호출 제한이 작동한다 (사고 10건 뒤 9번째 추가 요청부터 429 "잠시 후에 다시 해 주세요")
- [x] 응답 본문·헤더와 화면 코드에 키 흔적이 없고, 공개 코드에 서버 이름이 없다. `/supabase/…`, `/lib/…`, `/.env`는 404
- [x] 화면이 서버실처럼 보인다 (로컬 확인: 폭 375px에서 가로 스크롤 없음). 배포 화면은 사용자가 직접 확인
- 참고: `/api/incidents.js`는 함수 주소의 다른 표기라서 404가 아니라 405로 응답하고, 소스 코드는 나오지 않는다.

### 막혔던 점

- 서버 함수가 502를 돌려주었다. 로그에 `status: 403`이 남아 있어 원인이 테이블 읽기 권한임을 알았다. Data API 자동 공개를 끈 프로젝트라 서버 전용 역할에 `grant select`가 필요했다.
